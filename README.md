# Niche Radar v1.1 — 新词 / 老词需求挖掘 Chrome 插件

**这次版本核心变化：按任务倒计时，到点提醒，而非每天固定时刻提醒。**

兼容 Chrome Manifest V3，默认本地运行，可选 Supabase 云端保存，不抓取 Trends Bar 的数据。

## 下载 / 安装

1. 解压 `Niche-Radar-Chrome-Extension-v1.1.zip`。
2. Chrome 输入 `chrome://extensions`，打开 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择有 `manifest.json` 的 `niche-radar-extension` 文件夹。
4. 点击工具栏扩展图标打开侧边栏，也可点 ↗ 在独立标签页打开。

**已有 v1.0 用户**：最好先在旧版「设置」导出 JSON 备份。将 v1.1 文件覆盖原来加载的文件夹，然后在扩展管理页点击「重新加载」。保留同一个扩展 ID 时，Chrome 的本地线索、进度会保留。若改用了另一个文件夹导致扩展 ID 变化，可通过 JSON 恢复。

## 任务倒计时如何使用

1. 进入「今日清单」，每个任务下方都有 **计划 X 分钟**，直接修改可设置 1—240 分钟。
2. 点击这个任务的 **▶ 开始计时**，插件才会开始倒计时，不存在每天几点的固定提醒。
3. 可以 **⏸ 暂停** / **▶ 继续** / **↺ 重置**。
4. 倒计时到 0 时，Chrome 发送系统通知「本项任务时间到了」。
5. 如果需要继续，点击 **＋ 5 分钟**；或勾选任务完成。任务完成时会结束这项任务的计时。
6. 修改正在运行任务的计划时间会根据分钟数差额调整剩余时间：例如计划 20 分钟，已经用了 5 分钟，修改成 30 分钟，剩余时间变成约 25 分钟。

- **一刻只能有一个正在计时的任务**。切换到另一个任务会确认是否替换当前计时。
- 已暂停的任务不会到点通知，点继续才重新安排提醒。
- 到点只通知一次，不会自动切换下一项任务。
- 关掉侧边栏后继续计时；计时状态保存在 `chrome.storage.local`，由 `chrome.alarms` 在截止时间唤醒后台。
- 如果电脑休眠、Chrome 退出或系统抑制通知，则 **无法保证准点弹出**。Chrome 恢复后，后台会检查是否过期并补发提醒。
- 「设置」可统一修改各任务时长、恢复默认 90 分钟，并测试系统通知。**已取消 v1.0 每日固定时间、每周固定时间的通知。**

## 需求挖掘 SOP（原有功能保持）

- 新词：Trends Bar 批量趋势（12 分钟）、GitHub / HN / Product Hunt 日轮换（8 分钟）、Google 自动补全（5 分钟）。
- 老词：TrustMRR / Toolify / 插件生态轮换（20 分钟）、从竞品反查非品牌词（15 分钟）。
- 验证：SERP 与付费证据（20 分钟）；归档（10 分钟）。
- 每天 7 项，默认合计 90 分钟；现在每一项时长都能修改，顶部汇总自动更新。
- 新词 / 老词线索库、A/B/C 分级、到期复查、7 天数据概览均保留。
- 支持 CSV（Excel）导出、JSON 全量记录和设置备份、JSON 恢复。
- 可以与 Trends Bar 同时使用。在右上角点 ↗，以新标签页使用 Niche Radar。

## 数据与升级兼容

`chrome.storage.local` 中的 v1.0 线索 `nr_records` 和完成进度 `nr_progress` 继续沿用。新的 `nr_settings.taskMinutes` 保存 7 项任务时长，`nr_timer` 保存当前的倒计时状态。旧版 JSON 可以导入，未包含时长时会使用默认的 90 分钟任务计划。正在运行的计时器**不包含在导出的 JSON 中**，换电脑需要重新开始计时；这避免了跨设备导入时产生意外的过期提醒。

隐私：默认数据留在本机。配置 Supabase 后，仅在手动上传时发送线索、进度和任务时长；连接项目时请求该项目域名访问权限。

## Supabase 配置

1. 在 Supabase 项目的 SQL Editor 执行 `supabase.sql`，创建 `niche-radar-backups` 表，所有列也带 `niche-radar-` 前缀。SQL 中这些名称须用双引号。
2. 在 Authentication 中创建邮箱和密码账号，确保邮箱已确认。
3. 重新加载扩展，在「设置 → Supabase 云端保存」填写项目 URL、publishable key（或 anon key），然后登录。不要填 service_role / secret key。
4. 点击「上传本机数据」保存当前账号的一份最新快照；「从云端恢复」替换本机线索、进度和时长，并结束本机计时。恢复前的本机数据另存于 `nr_before_cloud_restore`。

当前为手动云端备份，不是自动双向同步。多设备上传会覆盖同一账号的上一份备份。运行中的倒计时不上传。RLS 限制账号仅能访问自己的数据；项目地址和公开密钥存于本机，密码不保存，会话存于浏览器 session 存储，重启浏览器后重新登录。

支持标准 `https://项目编号.supabase.co` 地址。需要联网及 Supabase Email/Password 登录服务。建表和实际联网读写需要在你的 Supabase 项目完成验证。
