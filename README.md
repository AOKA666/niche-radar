# Niche Radar

用于每日新词与老需求研究的 Chrome 侧边栏插件。支持任务计时、到点弹窗、实际用时记录、统一线索库，以及可选的 Supabase 云端备份。

采用 Manifest V3，最低支持 Chrome 116。原生 JavaScript 实现，无需安装依赖或构建即可加载。当前清单版本为 `1.1.0`。

## 安装与更新

1. 下载并解压仓库，或克隆到本机。
2. 打开 `chrome://extensions`，开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的项目根目录。
4. 将 Niche Radar 固定到工具栏，左键点击图标打开侧边栏。面板右上角的 ↗ 可打开独立标签页。

更新代码后，在扩展管理页点击「重新加载」。更新前建议在设置页导出 JSON；沿用同一扩展 ID 可保留本机数据。不要通过卸载扩展来更新，否则本机数据可能丢失。

## 每日研究流程

**每天都看新词，包括周末**：趋势扫描、增长证据整理、Google 搜索补全检查。在此基础上，按星期叠加任务：

| 日期 | 额外研究重点 |
| --- | --- |
| 周一 | 集中整理增长候选与证据 |
| 周二 | 老需求发现、竞品任务词拆解 |
| 周三 | 老需求补充、细分人群与痛点研究 |
| 周四 | SERP、搜索需求与商业可行性验证 |
| 周五 | 付费证据与最终选题验证 |
| 周末 | 归档，并为 MVP、上线和首次推广留出时间 |

页面已移除「周二 · 老词发现」等星期说明看板，直接展示当日任务卡。每张卡可展开操作步骤和来源入口。跨天仍在计时的任务会继续显示。

新词以 Google Trends / Trends Bar 的搜索增长证据为主。老需求研究以已有产品、收费证据、用户反馈为线索，按人群、地区、功能、格式继续细分。没有合格机会时允许不上线，不要求凑够候选数量。

任务库共有七类任务，默认时长合计 90 分钟；**这不是每天必须执行 90 分钟**。今日计划只汇总当前展示的任务，时长可以自行修改。

## 计时、暂停和完成

1. 在任务卡设置预计时长：每项 **1—240 分钟**。
2. 点击「开始计时」。同时只能有一个当前计时任务。
3. 运行中可暂停、继续、重置，也可提前点击「✓ 完成」。
4. 到点后弹出独立提醒窗口，同时发送系统通知。可以输入 **1—240 分钟**继续计时，或直接完成任务。
5. 面板中的「自定义延长」也可输入延长分钟数；每次延长后的计时到点会再次提醒。

工具栏图标显示剩余分钟数，每分钟更新；暂停时为黄色，到点时为红色。右键图标可暂停或继续，左键仍打开侧边栏。关闭侧边栏不会停止计时，平时不会另开倒计时窗口。

修改当前任务的计划时长会按差额调整剩余时间。例如从 20 分钟改为 30 分钟，剩余时间增加 10 分钟。重置会开始新一轮计时，不会把被重置的轮次记为完成。

### 预计与实际用时

点击完成后，本机会保存：任务、所属日期、开始时刻、完成时刻、开始时的预计用时和累计实际用时。任务卡展示今天最近一次完成记录。

- 预计用时以本轮开始时的计划为准，后续延长不改写原预计值。
- 实际用时累计运行的计时段，包含延长后继续计时的时间；不包含暂停或到点后等待操作的时间。
- 实际用时不是电脑活动监测，也不等同于专注时间；未暂停时仍按计时经过的时间计算。
- 没有开启计时而直接勾选完成，只记录完成进度，不生成实际用时记录。
- 跨天任务归入开始计时的日期。旧版本已启动的计时缺少完整信息时，只能从可恢复的计时段统计。

电脑休眠、浏览器退出或系统限制通知时，无法保证准点提醒。浏览器恢复运行后会检查是否过期。禁用扩展后无法继续显示或提醒。

## 线索库与数据概览

新词、老词保存在同一个线索库，支持搜索、来源记录、编辑、删除及按类型和评级筛选。

可记录关键词、发现日期、来源及网址、对标产品、目标用户、用户需求、需求强度、搜索信号、竞争切口、付费证据、开发风险、复查日期和备注。

评级由用户根据证据填写：A 继续深入验证，B 待观察，C 放弃；未判断时为「待定」。数据概览展示近 7 天线索、执行进度、来源分布和到期复查项目。

## 导出、恢复与保存范围

| 数据 | 本机保存 | CSV 导出 | JSON 备份 / Supabase |
| --- | --- | --- | --- |
| 线索及证据字段 | 是 | 是 | 是 |
| 每日完成进度 | 是 | 否 | 是 |
| 任务计划时长 | 是 | 否 | 是 |
| 当前倒计时 | 是 | 否 | 否 |
| 预计 / 实际用时历史 | 是 | 否 | 否 |
| 云端连接配置与登录会话 | 是 | 否 | 否 |

JSON 恢复和云端恢复会替换本机线索、完成进度和时长，并结束当前计时。云端恢复前会将原本机数据另存为 `nr_before_cloud_restore`；目前没有对应的一键回滚界面。建议在恢复前另外导出 JSON。

**计时历史目前仅保存在本机，不随 JSON 或云端备份迁移。**

## Supabase 云端备份（可选）

不配置 Supabase 也可使用本机功能。当前云端功能是**手动上传、手动恢复**，不是自动双向同步；每个账号保留一份最新快照，多设备上传会覆盖同一账号之前的快照。

### 配置项目

1. 在 Supabase 项目的 SQL Editor 中执行仓库里的 `supabase.sql`。
2. 在该项目的 Authentication → Users 中创建邮箱密码账号，并确认邮箱。
3. 重新加载插件，进入「设置 → Supabase 云端保存」。
4. 填写项目 URL（`https://项目编号.supabase.co`）和 publishable key 或 anon key，允许连接该项目域名。
5. 使用第 2 步创建的账号登录，点击「上传本机数据」或「从云端恢复」。

**插件账号与 Supabase 管理后台账号不同。** 通过 GitHub 登录管理后台，不会自动创建插件可用的邮箱密码账号。不要在插件里输入 GitHub 密码；当前插件未实现 GitHub OAuth 登录。遇到 `Invalid login credentials`，请检查项目 Authentication 中是否存在该用户、邮箱是否确认以及密码是否正确。

### 表结构与权限

表名是 `niche-radar-backups`，所有数据库列也使用此前缀：

| 列名 | 用途 |
| --- | --- |
| `niche-radar-user-id` | 账号 ID，主键，关联 Auth 用户 |
| `niche-radar-data` | JSON 格式的线索、进度和任务时长快照 |
| `niche-radar-updated-at` | 最近上传时刻 |

名称包含连字符，SQL 中须使用双引号。快照内部沿用插件的数据结构。

建表脚本开启 RLS，限制登录账号只访问自己的记录，并撤销匿名角色的表权限；已有同名策略会保留，不执行删除策略操作。删除 Auth 用户时，该用户的云端备份会按外键规则一起删除。

仅使用 publishable / anon key，不能在插件中配置 service_role 或 secret key。连接配置保存在本机，密码不保存，会话使用 `chrome.storage.session`，重启浏览器后需重新登录。

仓库当前的 `cloud.js` 预填了项目地址与公开密钥。使用自己的 Supabase 项目时，请在配置页替换；公开密钥不授予管理员权限，数据访问由 RLS 控制。

## 权限与本机存储

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存线索、配置、计时与会话 |
| `alarms` | 后台倒计时提醒和图标更新 |
| `notifications` | 到点系统通知 |
| `sidePanel` | 主界面侧边栏 |
| `contextMenus` | 图标右键暂停 / 继续 |
| 可选 `https://*.supabase.co/*` | 配置时按项目请求连接权限 |

插件不自动抓取网站内容。云端上传需手动触发。

主要本机存储键：`nr_records`（线索）、`nr_progress`（完成进度）、`nr_settings`（时长）、`nr_timer`（当前计时）、`nr_time_history`（完成用时历史）、`nr_cloud_config`（连接配置）、`nr_before_cloud_restore`（恢复前备份）。`nr_cloud_session` 单独保存在 session 存储中。

## 开发与验证

编辑文件后重新加载扩展即可，无构建步骤。测试使用 Node.js 内置测试运行器；PowerShell 下可执行：

```powershell
Get-ChildItem tests -Filter '*.test.mjs' | ForEach-Object { node --test $_.FullName }
```

语法检查：

```powershell
node --check app.js
node --check background.js
node --check cloud.js
node --check reminder.js
```

自动测试覆盖核心数据处理、每周任务安排及后台计时逻辑，使用模拟 Chrome API；浏览器真实弹窗、系统通知以及 Supabase 登录和读写仍需实际环境验证。

建议手动检查：关闭面板后图标继续计时、右键暂停与继续、提前完成、到点弹窗、自定义延长，以及暂停时间不计入实际用时。

## 项目文件

```text
niche-radar/
├── manifest.json       # 扩展配置与权限
├── background.js       # 后台计时、图标、提醒与完成记录
├── core.mjs            # 任务配置、周计划和数据处理
├── sidepanel.html      # 主界面
├── app.js
├── style.css
├── reminder.html       # 到点提醒窗口
├── reminder.js
├── reminder.css
├── cloud.html          # Supabase 配置与备份
├── cloud.js
├── cloud.css
├── supabase.sql        # 建表与 RLS 策略

├── tests/
└── .gitignore
```

`.gitignore` 排除环境文件、私钥、日志、依赖、打包产物及按默认文件名导出的用户数据；源码、图标、建表脚本和测试保留在仓库中。
